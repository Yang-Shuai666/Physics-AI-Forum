## 本周目标

- 深入理解 ReAct Agent 的执行流程，结合论文与开源代码梳理核心实现。
- 尝试从零理解最小 ReAct 系统，明确 LLM、工具执行器、Observation 和循环控制之间的关系。
- 梳理 Function Calling、MCP、Agent Hooks 等相关机制，理解它们在 Agent 系统中的作用。
- 学习 SQL Agent 的基本架构，理解自然语言查询如何转化为数据库操作并返回结果。

## 做了什么

### 1. ReAct 原理与源码学习

- 阅读 ReAct 论文的引言、方法和结论部分，理解 ReAct 将推理（Reasoning）与行动（Acting）结合的核心思想。
- 结合开源实现，梳理 Agent 的主循环、环境交互、工具执行及结果回填等关键环节。
- 学习 `reset()`、`step()` 等环境交互接口的作用，以及环境包装器在任务执行与日志记录中的作用。
- 通过最小 ReAct 实现的学习，理解工具注册、Action 解析、工具路由、Observation 回填和终止条件等基本组成。

### 2. Function Calling、MCP 与 Hooks

- 对比 Function Calling 与 MCP：前者主要描述模型提出结构化工具调用请求的机制，后者提供模型应用与外部工具服务之间的标准化交互协议。
- 梳理工具定义、模型决策、工具执行和执行结果返回之间的关系，进一步明确 LLM 本身并不直接执行外部工具。
- 学习 Agent Hooks 的基本概念，理解其作为生命周期扩展点，可以在模型调用等关键阶段插入额外逻辑。

### 3. SQL Agent 工作流程

- 以自然语言查询数据库为例，学习 SQL Agent 的基本工作链路：理解用户问题、检查数据库 Schema、生成 SQL、执行查询并组织答案。
- 理解数据库 Schema 对 SQL 生成的作用，包括提供表名、字段名及相关结构信息，帮助模型生成更符合数据库实际情况的查询。
- 梳理 SQL 执行失败后的错误反馈与修正重试机制，理解 Agent 如何利用执行结果继续推进任务。
- 了解数据库只读权限、查询限制等安全控制的重要性。

## 结论与数据

- ReAct 的核心不是单次生成答案，而是通过“推理—行动—观察”循环，根据工具执行结果继续决策。
- 工具调用链路需要明确区分模型决策与程序执行：LLM 负责提出调用请求，应用程序负责校验、路由和执行工具，并将结果反馈给模型。
- Function Calling 与 MCP 解决的问题并不完全相同：前者侧重模型发起结构化工具调用，后者侧重工具服务的标准化接入与交互。
- SQL Agent 将大模型的自然语言理解能力与数据库查询工具结合，可以处理需要动态生成查询语句的问题；其可靠性仍取决于 Schema、错误处理、权限控制和结果验证。
- 本周以原理学习、源码阅读和最小实现理解为主，SQL Agent 尚需进一步完成代码实践与端到端验证。

## 问题与讨论点

1. 如何将最小 ReAct 实现扩展为更健壮的 Agent，包括工具注册、异常处理、调用次数限制和终止条件？
2. LangChain 等框架封装的 Agent 执行循环与手写 ReAct 的实现有什么区别？框架具体封装了哪些能力？
3. MCP 接入工具后，工具发现、参数校验、执行权限和错误处理分别由哪些组件负责？
4. SQL Agent 如何避免错误 SQL、越权查询和高成本查询？仅依赖 Prompt 与 Schema 是否足够？
5. 如何设计可复现的评测方案，比较不同 Agent 在任务成功率、工具调用次数、执行成本和错误恢复能力上的差异？
